svelte-stageshow

A Svelte 5 port of Stageshow, Benji Taylor's MIT kit for framed faux product UI: a believable interface, cropped with intent, as one still or a short scripted demo.

Everything upstream is here: 69 scenes, 42 stylesheets carried over unchanged, 44 brand marks, and the design tokens the whole kit is built on. Nothing from React ships — svelte is the only peer dependency.

Install

Not published to npm yet. The 0.2.0 tarball installs today and is the same build that would be published: 

pnpm add https://github.com/maven-ammar/svelte-stageshow/releases/download/v0.2.0/svelte-stageshow-0.2.0.tgz

Once the registry publish lands, that becomes pnpm add svelte-stageshow.

Quick start

Two components and a stylesheet. Stage sets the design size and scales to its container; Window draws the chrome. Your product's own markup goes inside. 

<script lang="ts">
  import { Stage, Window } from 'svelte-stageshow'
  import 'svelte-stageshow/style.css'
</script>

<Stage width={720} height={340}>
  <Window url="acme - invoices">
    <!-- your product, built from the kit's parts -->
  </Window>
</Stage>

Add a script and the stage plays it on a loop: an Act aims at elements by name, changes state, waits for paint, and moves the cursor. 

async function script(a: Act<State>) {
  await a.click({ at: 'share' })   // the cursor arcs there and presses
  await a.set({ open: true })      // resolves once it has painted
  await a.wait(2000)               // the payoff holds
  await a.click({ at: 'close' })
  await a.set({ open: false })
}

Stage props

width and height are the design size. The stage scales down to fit its container and only grows past the design size with fill.

widthnumberrequired

Design width.

heightnumberrequired

Design height.

initialS—

Scene state at the start of each loop. Statics can leave it out.

scriptScript<S>—

Loops while on screen. Leave it out for a static illustration.

posterSinitial

The still frame shown under reduced motion, or with no script.

playPlayloop

How the script runs.

cursorCursorConfig—

Which pointer the scene uses, and how it behaves.

compactCompactConfig—

A second, smaller design for narrow containers.

keysKeysAtbottom

Where keycaps from act.key appear.

hoverstring[]—

Targets shown hovered in a still.

themeThemelight

Light or dark, from the same scene code.

palettePaletteaccent

One accent, or mono.

fidelityFidelitystandard

How many real words a look uses.

greys'warm' | 'cool'—

Swaps the warm canvas and well for cool ones. Light theme only.

tokensLookTokens—

A look as values: any --ss-* token.

accentstring—

The accent colour for this stage.

groundGround—

What the scene sits on. orbs is a pale tile lit by soft colour orbs.

fillbooleanfalse

Grow past the design size to fill the container, up to 2x.

speednumber1

Plays the script faster above 1, slower below.

specimenbooleanfalse

Renders the stage as a specimen rather than a scene.

unframedbooleanfalse

Drops the stage's own frame.

deterministicbooleanfalse

CSS transitions off, a virtual 60fps clock drives waits, tweens and typing, so the same frame index renders the same DOM.

Draws the window as if it were behind another.

Props for the content column; class merges with the body class.

Looks and tokens

A look is a theme, a palette and how many real words the scene uses. The kit's colours, type, radii and spacing are all design tokens, so you can map your own design system onto them and the demo will use your real colours and corner radii instead of looking like a mock-up.

Pass a theme from a prop, or any --ss-* token through tokens. getLook, setLook and useLook read and write the surrounding look when a scene is nested inside another.

Scenes
